# MyMini 기술서

이 문서는 **지금 저장소에 구현된 코드**를 기준으로 씁니다. 아직 만들지 않은 부분은 [7. 다음 단계](#7-다음-단계-로드맵)에 따로 모았습니다.

---

## 1. 전체 구조

```
   브라우저 (종원)     브라우저 (민수)     브라우저 (지현)
          │                  │                  │
          └──────── WebSocket ┼──────────────────┘
                              ▼
                ┌──────────────────────────┐
                │   FastAPI 서버 (main.py)  │
                └────────────┬─────────────┘
                             ▼
                ┌──────────────────────────┐
                │ Orchestrator             │  "지금 누가 말해야 하지?"
                │ (orchestrator.py)        │
                └──┬──────────┬─────────┬──┘
                   ▼          ▼         ▼
              LLM 어댑터    검색 Tool   Hub (저장소)
              (llm.py)    (tools.py)  (store.py)
                   │          │         │
               OpenAI API  Tavily API  메모리 (→ 이후 PostgreSQL)
```

- **사람 메시지와 AI 메시지는 같은 통로(WebSocket)로** 방 전체에 뿌려집니다. 화면 입장에서는 둘 다 똑같은 "메시지"입니다.
- **API 키가 없으면 MOCK 모드**로 돌아갑니다. 키워드 기반 가짜 응답이 나오므로 인터넷이나 키 없이도 시연할 수 있습니다.

## 2. 기술 스택

| 영역 | 지금 (MVP) | 다음 단계 |
|---|---|---|
| 프론트엔드 | 순수 HTML/JS (`app/static/client.html`, `demo-v1.html`) | Next.js + TypeScript + Tailwind |
| 백엔드 | **FastAPI** (Python) | 그대로 |
| 실시간 통신 | **WebSocket** (FastAPI 기본 기능) | 그대로 |
| LLM | **OpenAI** (`gpt-4o-mini` 기본), JSON 응답 모드 | 모델 교체 가능 |
| Agent 구조 | 자체 Orchestrator (점수 → 선택 → 발언 반복) | 필요하면 LangGraph |
| 검색 | **Tavily** API (키 없으면 모의 결과) | 그대로 |
| 저장소 | 인메모리 `Hub` | PostgreSQL + pgvector |
| 배포 | Railway / Render | 프론트는 Vercel |

> 왜 FastAPI인가? Agent 로직이 Python이라 바로 붙이기 쉽고, WebSocket이 기본으로 들어 있어서 추가 라이브러리가 필요 없습니다.

## 3. 파일 구조

```
mymini-backend/
├── app/
│   ├── main.py          # FastAPI 앱. HTTP API + WebSocket 입구
│   ├── orchestrator.py  # 회의 진행자. 누가 말할지 고르고 AI끼리 토론시킴
│   ├── llm.py           # LLM 호출 모음 (점수/발언/풀어쓰기/요약/회의록) + MOCK
│   ├── tools.py         # 자료조사 Tool (Tavily 검색)
│   ├── store.py         # Hub: 방, 소켓, 메시지 저장 + 기본 페르소나 3명
│   ├── models.py        # 데이터 모양 정의 (Persona, Message, Room)
│   ├── config.py        # 환경변수와 튜닝 값
│   └── static/
│       └── client.html  # 실제 서버에 붙는 간단한 채팅 클라이언트
├── demo-v1.html         # 서버 없이 혼자 도는 발표용 데모 화면 (시나리오 자동 재생)
├── docs/                # 기획서, 기술서, 데모 시나리오 (이 문서들)
├── .env.example         # 환경변수 예시
├── requirements.txt
└── README.md
```

## 4. 데이터 모델 (`models.py`)

### Persona: 미니미의 성격

| 필드 | 예시 | 설명 |
|---|---|---|
| `user_id` | `minsu` | 고유 ID |
| `name` | 민수 | 표시 이름 |
| `role` | 백엔드 개발 | 역할 / 전문 분야 |
| `tone` | 신중한 말투. 걱정을 먼저 말하고 '~듯'을 자주 쓴다. | 말투 |
| `traits` | 구현 기간과 난이도에 민감. 범위를 줄이는 쪽을 선호. | 의견 성향 |
| `memory` | `["발언: 범위 줄이자", ...]` | 장기 기억 (최근 20개) |

### Message: 채팅방 메시지 한 개

| `kind` | 뜻 | 누구에게 |
|---|---|---|
| `human` | 사람이 직접 쓴 말 | 전체 |
| `mini` | 미니미 발언 (`proxy=true`면 대리 참여) | 전체 |
| `system` | 입장, 자리 비움 같은 안내 | 전체 |
| `tool` | 검색 결과 | 전체 |
| `result` | 회의 결과 정리 | 전체 |
| `digest` | 부재 중 요약 | **본인에게만** |

### Room: 회의방

`agenda`(안건), `personas`(참여자), `away`(누가 자리 비웠는지), `away_marker`(언제부터 비웠는지), `messages`(대화 기록)

## 5. 핵심 로직: 오케스트레이터

### 5-1. 누가 말할지 정하기

사람이 말하면 오케스트레이터가 **최대 `MAX_ROUNDS`(기본 4)번** 아래 과정을 반복합니다. 이 반복 덕분에 AI끼리 대화가 이어집니다.

```
새 메시지 도착
    │
    ▼
① LLM에게 묻기: "각 미니미가 지금 끼어들 필요가 얼마나 돼? (0~1)"
    │      예) 종원 0.4 / 민수 0.9 / 지현 0.5
    ▼
② 점수 보정
    · 자리 비운 사람의 미니미  → +0.3     (주인이 없으니 더 적극적으로)
    · 참여 중인 사람의 미니미  → ×0.85    (주인이 있으니 덜 끼어듦)
    · 방금 직접 말한 사람의 미니미 → 0   (자기 주인한테 대답하지 않기)
    · 방금 말한 미니미         → 0       (연속 발언 금지)
    ▼
③ 가장 높은 점수가 기준선을 넘으면 그 미니미가 발언
    · 기준선 = 0.6 + 0.05 × 라운드   (라운드가 갈수록 깐깐해져서 대화가 자연스럽게 끝남)
    ▼
④ 아무도 기준선을 못 넘으면 → 멈춤 (조용해짐)
   누가 말했으면 → ①로 돌아가 다음 라운드
```

각 라운드의 점수와 선택 이유는 `orchestrator` 이벤트로 화면에 보내집니다. 그래서 **"왜 이 AI가 말했는지"를 눈으로 볼 수 있습니다.** 데모에서 큰 설득 포인트입니다.

> 동시에 여러 토론이 겹치지 않도록 방마다 `asyncio.Lock`을 씁니다. 토론 중에 들어온 새 메시지는 기록만 해 두고, 다음 라운드 점수 계산에 반영됩니다.

### 5-2. 미니미가 말하기

LLM에게 아래 정보를 줍니다.

- 내 말투, 성향, 최근 기억 5개
- 안건과 최근 대화 30개 (단기 기억)
- 자리 비움 상태면 *"주인이 예전에 한 말을 근거로만 말하고, 근거 없는 약속은 하지 마"*
- *"이미 나온 말을 반복하지 말고 질문, 반박, 보완, 동의 중 하나를 해"*

그러면 LLM이 `{"text": "...", "search": "검색어 또는 null"}`을 돌려줍니다.
`search`가 있으면 **검색 Tool을 실행해서 결과를 `tool` 메시지로 방에 올립니다.** 다음 라운드에서 미니미들이 이 결과를 보고 다시 논의합니다.

### 5-3. LLM 호출 5종 (`llm.py`)

| 함수 | 언제 | 출력 |
|---|---|---|
| `score` | 매 라운드 | 미니미별 점수 + 한 줄 이유 |
| `reply` | 선택된 미니미 발언 | 발언 + 검색어 |
| `expand` | 사람이 "미니미에게 맡기기" 모드로 한 줄 입력 | 주인 말투로 2~3문장 풀어쓰기 (없는 주장은 추가 금지) |
| `digest` | 자리 비움 해제 | 결정된 것, 열린 질문, 내 미니미가 대신 한 말 (3~5줄) |
| `minutes` | 회의 종료 | 안건, 주요 의견, 의견 충돌, 결론 |

모든 호출은 `response_format=json_object`로 **항상 JSON**을 받아서 파싱 오류를 줄입니다.

### 5-4. 기억 (Memory)

| 종류 | 지금 | 다음 단계 |
|---|---|---|
| 단기 기억 | 방의 최근 메시지 30개를 프롬프트에 넣음 | 그대로 |
| 장기 기억 | 페르소나별 텍스트 리스트 (최근 20개, 프롬프트엔 5개) | pgvector에 저장하고 **안건과 비슷한 과거 기억만 검색**해서 넣기 |

## 6. API 명세

### HTTP

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/` | 채팅 클라이언트 (`client.html`) |
| GET | `/health` | 서버 상태, `mock`/`openai` 모드 |
| GET | `/rooms/{room_id}/messages` | 대화 기록 |
| GET | `/rooms/{room_id}/personas` | 참여자 페르소나 목록 |
| PUT | `/rooms/{room_id}/personas/{user_id}` | 미니미 생성/수정 `{name, role, tone, traits}` |

### WebSocket: `ws://HOST/ws/{room_id}/{user_id}`

**클라이언트 → 서버**

| type | 필드 | 설명 |
|---|---|---|
| `message` | `text`, `mode` (`direct` / `delegate`) | 직접 말하기 / 한 줄만 쓰고 미니미가 풀어쓰기 |
| `away` | `value` (bool) | 자리 비움 켜기/끄기 |
| `agenda` | `text` | 안건 설정 |
| `end_meeting` | - | 회의 결과 정리 |
| `ping` | - | 연결 확인 |

**서버 → 클라이언트**

| type | 설명 |
|---|---|
| `history` | 접속 직후 최근 100개 메시지 + 안건 |
| `message` | 새 메시지 (`kind`로 종류 구분) |
| `presence` | 참여자 온라인/자리 비움 상태 |
| `orchestrator` | 라운드별 점수, 기준선, 선택된 미니미, 이유 |
| `typing` | 미니미가 입력 중 |
| `agenda` | 안건 변경 |
| `activity` | "검색 에이전트 실행: …" 같은 활동 로그 |

### 환경변수 (`.env`)

| 이름 | 기본값 | 설명 |
|---|---|---|
| `OPENAI_API_KEY` | (빈 값) | 비우면 MOCK 모드 |
| `OPENAI_MODEL` | `gpt-4o-mini` | 사용할 모델 |
| `TAVILY_API_KEY` | (빈 값) | 비우면 모의 검색 결과 |
| `SPEAK_THRESHOLD` | `0.6` | 미니미가 말하기 위한 최소 점수 (높을수록 조용해짐) |
| `MAX_ROUNDS` | `4` | 사람 메시지 하나당 AI끼리 이어갈 최대 턴 수 |

## 7. 다음 단계 (로드맵)

| 우선순위 | 할 일 | 이유 |
|---|---|---|
| 1 | PostgreSQL로 저장 (`store.py`의 `Hub` 교체) | 서버를 재시작하면 대화가 사라짐 |
| 2 | pgvector 장기 기억 | 지난 회의 내용을 근거로 말하게 하기 |
| 3 | 과거 채팅/문서 업로드 → 말투와 성향 자동 추출 | 미니미를 직접 입력하는 수고 줄이기 |
| 4 | Next.js 프론트 | 화면 완성도 |
| 5 | 로그인 (Google OAuth / Supabase Auth) | 지금은 URL의 `user_id`만으로 입장하므로 아무나 남의 이름으로 들어올 수 있음 |
| 6 | 미니미 발언 권한 설정 | "의견 전달만" / "동의까지 가능" 등 대리 범위를 주인이 정하기 |

## 8. 알려진 한계

- **인메모리 저장**: 서버를 재시작하면 모든 방과 대화가 초기화됩니다.
- **인증 없음**: 데모용입니다. 공개 배포 전에 로그인을 붙여야 합니다.
- **단일 서버 전제**: 소켓과 락이 프로세스 메모리에 있어서 서버를 여러 대로 늘릴 수 없습니다. (나중에 Redis pub/sub 필요)
- **LLM 비용**: 사람 메시지 하나에 최대 `점수 4회 + 발언 4회` 호출이 생깁니다. `MAX_ROUNDS`로 조절하세요.
