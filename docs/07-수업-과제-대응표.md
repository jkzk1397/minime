# 수업 과제 대응표 — 계획서·보고서 ↔ 코드

생성형 AI 기초 4조 생성까스. 해커톤 시제품을 수업 과제 기준으로 이어 만들면서, 각 문서에 적은 내용이 코드 어디에 있는지 정리했어요.

| 개인정보 처리방침 확인 영역 | 동의 화면 '법적 근거' 접기 + 메뉴 › 개인정보 동의 내용 |
| 외부 전송 안내 | 설정을 읽어 자동 표시: API를 쓰면 전송 대상 주소, 로컬이면 "외부로 보내지 않아요" |

시제품 설계안이라 실제 운영 전에는 법적 검토가 다시 필요하다고 화면에도 적었어요.

## 3. 멀티모달 보고서 (온보딩 카드 5장)

- 카드 문구는 보고서 그대로 쓰고, 그림은 같은 캐릭터 규칙으로 SVG를 다시 그렸어요 (사용자 진한 파랑 · 팀원 연보라·하늘색).
- 보고서 5.2 남은 개선점 "미니미 전용 반투명 발광 표현"을 반영: 미니미는 **반투명 + 점선 테두리 + 반짝이**로 사람 캐릭터와 구분돼요.
- 마지막 카드 다음엔 '내 미니미 준비 › 입장 만들기'로 바로 이어져요.
- 카드 02에 한 줄 추가: "보고서가 없으면 1분 빠른 입장 체크로도 준비할 수 있어요."

## 5. 문서 없이 미니미 만들기 — 조사와 판단

보고서 업로드만으로는 실용성이 떨어진다는 의견이 있어, 비슷한 서비스들이 '나 대신 회의에 가는 AI'를 어떻게 만드는지 찾아봤어요.

- Zoom은 2026년 3월, 회의에 못 갈 때 내 디지털 분신을 보내고, 미리 준비한 정보로 질문에 답하게 하는 AI 아바타를 발표했어요 ([chatai.com](https://www.chatai.com/posts/zoom-launches-ai-office-suite-with-meeting-avatars-and-deepfake-detection)).
- WeClone 같은 도구는 내 채팅 기록 수천 개로 모델을 미세 조정해 말투를 따라 해요. 단체방은 여러 사람 말이 섞여 품질이 떨어지고, 다른 사람이 내 대화로 분신을 만들 수 있다는 동의 문제가 지적돼요 ([themenonlab.blog](https://themenonlab.blog/blog/weclone-ai-digital-twin-from-chat-history)).
- 브라우저 음성 인식은 `processLocally` 로 기기 안에서만 인식하도록 요청할 수 있고, `available()` 로 가능한지 먼저 확인할 수 있어요 ([MDN processLocally](https://developer.mozilla.org/docs/Web/API/SpeechRecognition/processLocally), [MDN available()](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/available_static)).

MINIME의 판단:

| 방식 | 채택 | 이유 |
| --- | --- | --- |
| 말투를 배우는 미세 조정 | 안 함 | 우리 목표는 말투가 아니라 **확인된 입장**을 전하는 것. 데이터·GPU 부담과 동의 문제가 큼 |
| 단톡방 대화 가져오기 | 함 (제한) | 브라우저에서 **내 말만** 골라 보내고 다른 사람 말은 버림. 입장은 초안으로만, 본인이 확인해야 근거 |
| 빠른 입장 체크 | 함 | 문서 없이 1분. 고른 그대로 쓰므로 AI가 덧붙일 여지가 없음 |
| 전달 메모 | 함 | 학생들이 실제로 하는 "이거 전해 줘"를 그대로. 미니미가 고치지 않음 |
| 미니미 파일 | 함 | 팀플 회의는 여러 번. 서버에 계정 없이도 내 미니미를 들고 다님 |
| 말로 입력 | 함 | 휴대폰에서 인터뷰·메모를 말로. 기기 안 인식이 안 되면 서버 전송을 먼저 알림 |
| 영상 아바타 | 안 함 | 실존 인물 모방·딥페이크 위험(계획서 08 저작권·초상권 점검)과 맞지 않음 |
