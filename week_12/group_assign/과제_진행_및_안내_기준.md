# 12주차 과제 진행 및 안내 기준

- 기준 출처: 사용자가 대화에 제공한 과제 안내문과 추가 수정 요청
- 용도: HTML·Colab 노트북을 수정할 때 누락 여부를 대조하는 작업 기준
- 적용 순서: 사용자의 최신 지시 → 과제 요구사항 → 아래 구현·작성 원칙
- 구분: 아래 과제 요구사항은 안내문을 정리한 내용이며, MINIME 작업 배정과 구성은 현재 작업안이다.

## 고정된 작업 방향

- 팀 적용 방식: **② 기존 기능 개선** 한 가지
- 팀 문제: 기존 문서·채팅의 입력 처리 정확성과 반복 처리 효율 개선
- 개인 작업: 5개, 담당자 1명씩 배정
- 교차 검증: 김동준 → 김혜중 → 노재원 → 송준서 → 정종원 → 김동준
- 검증 환경: Colab의 시험용 문자열로 실제 프로젝트 함수 실행
- 프로젝트 반영: 검증한 변경을 실제 소스 파일에 반영하고 통합본 재검증
- 기능 범위 유지: 줄바꿈 통일·긴 문단 분할·짧은 채팅 보존·40문단 후 처리 종료·문장 기호 지원
- 제출물: 실행 출력이 저장된 **Colab 노트북 공유 링크 1개**

## STEP 1. 해결할 문제와 기대 결과 확정

다음 여섯 항목을 조별로 작성한다. 노트북의 STEP 1에서 직접 확인할 수 있게 배치한다.

1. 프로젝트의 목적과 현재 구현 상태
2. 선택한 적용 방식과 해결할 문제
3. 작업이 필요한 이유
4. 사용할 자료 또는 수정할 기존 코드
5. 작업 후 기대하는 실행 결과
6. 조원별 담당 범위와 완료 기준

- 기대 결과는 추상적인 개선 표현 대신 **어떤 입력에서 어떤 출력이 나와야 하는지** 작성한다.
- 역할표 형식: 이름 / 담당 구현·수정 작업 / 완료 기준 / 교차 검증자
- 작업 수뿐 아니라 난이도·소요 시간도 고려한다.
- 자료 취합·회의 기록·제출만으로 개인 역할을 대신할 수 없다.
- 통합은 한 명의 전담 작업으로만 두지 않고 담당별 연결 범위를 기록한다.

## STEP 2. 작업 자료와 처리·수정 기준 준비

| 작업 성격 | 준비할 내용 |
| --- | --- |
| 데이터 처리·분석 | 원자료, 출처·수집일, 열·자료형·범주 기준, 중복·결측값 처리 기준 |
| 기능 추가 | 입력 예시, 처리 조건, 출력 형태, 기존 프로젝트 연결 부분 |
| 오류 수정 | 기존 코드, 오류 메시지 또는 잘못된 결과, 발생 조건, 기대 동작 |
| 코드 구조 개선 | 기존 코드, 필요한 이유, 개선 후 유지되어야 할 동작 |

- 현재 선택한 작업에 해당하는 기준을 작성한다. 불필요한 작업 유형을 새로 수행할 필요는 없다.
- 작업 전 원자료와 기존 코드를 별도로 보관한다.
- 개인정보는 AI 입력 전에 제거한다.
- 합성 자료는 **시험용**이라고 표시하고 구성 조건을 기록한다.
- 원자료에 없는 문장·의견·숫자를 AI가 임의로 추가했는지 대조한다.
- 중복·결측 처리에 해당하지 않는 작업은 적용하지 않는 이유와 범위를 표시한다.

## STEP 3. 개인별 AI 활용과 구현·수정

과제 안내는 각 조원이 직접 AI에게 요청하고 관련 코드를 실행하도록 요구한다.

### 프롬프트 필수 항목

다섯 프롬프트 **각각의 본문 안에** 다음 내용을 모두 포함한다. 주변 설명만으로 대체하지 않는다.

1. 담당 작업의 목적
2. 입력 자료 또는 관련 코드: 파일·함수 및 다음 코드 셀의 실제 원문 참조
3. 처리 조건·현재 증상·기대 결과: 입력 예시와 구체적인 출력 기준
4. 프로젝트 언어·도구: Python, Google Colab
5. 다른 담당 부분과 연결할 방식: 공통 함수의 수정 구간 또는 함수 호출·반환 형식 유지

- 필수 내용은 같되 말투·길이·전개 방식을 담당별로 다르게 작성한다.
- 프롬프트 내용만 바꿀 때는 구현된 기능·시험 기준과 모순되지 않게 확인한다.
- AI 설명을 확인하고 실행한다. 예상과 다르면 실제 출력 근거를 제시해 수정 요청한다.
- 실패·수정 요청·학생의 직접 활동을 수행한 사실 없이 만들어 쓰지 않는다.
- 작성용으로 다듬은 프롬프트와 실제 사용 대화 이력은 구분한다.

### 개인별 기록

- 사용한 핵심 프롬프트 및 기록의 출처
- AI 제안 중 채택·변경한 내용과 이유
- 구현·수정 코드 또는 데이터 위치
- 입력·처리·출력 및 실행 결과에서 확인한 사실
- 무료 생성형 AI 활용 가능, 유료 서비스·API 사용은 필수 아님

## STEP 4. 조원 간 교차 검증

- 5인 순환 배정: ① → ② → ③ → ④ → ⑤ → ①
- 각 조원은 다른 조원의 결과 한 가지를 검증한다.
- 별도 검증 프로그램 작성은 필수 아님. 실행 가능한 입력과 확인 근거는 필요하다.

검증 대상에 해당하는 항목을 확인한다.

- 완료 기준 충족 여부
- 입력과 실제 출력이 기대 동작에 맞는지
- 처리 기준이 원자료에 정확히 적용됐는지
- 계산값이 일부 자료의 직접 계산값과 맞는지
- 같은 오류 조건에서 문제가 해결됐는지
- 구조 개선 후 기존 동작이 유지되는지
- 표·그래프 사용 시 분석 수치와 일치하는지

문제가 있으면 검증자가 근거를 기록하고 제작자가 수정·재실행한다. 문제가 없어도 입력·조건·정상 동작 근거를 기록한다. AI 설명만으로 검증을 마치지 않는다.

## STEP 5. 프로젝트 반영 및 최종 동작 확인

- 다섯 개인 변경을 실제 프로젝트 소스에 통합한다.
- 각 담당의 연결 범위와 통합 결과를 확인한다.
- 각 조원은 **서로 다른 상황의 시험 조건 한 가지**를 담당한다.
- 단순히 입력값만 바꾸는 것이 아니라 확인하려는 상황이 달라야 한다.
- 정상 입력·조건 변경·자료 없음·결측·중복·기존 오류·구조 개선 전후·자료 추가 중 프로젝트에 맞는 조건을 선택한다.
- 전체 동작 확인은 조원 모두 참여하도록 배정한다.

시험 기록 형식:

| 담당자 | 시험 조건·입력 자료 | 예상 결과 | 실제 결과 | 판정 및 수정 내용 |
| --- | --- | --- | --- | --- |

## 개인별 참여 기록과 참여 확인

과제 안내는 조원마다 자신의 이름으로 직접 작성하도록 요구한다.

| 기록 항목 | 포함할 내용 |
| --- | --- |
| 담당 작업 | 구현·수정 부분과 완료 기준 |
| AI 활용 | 핵심 프롬프트와 반영 내용 |
| 개인 결과물 | 코드·데이터 위치와 실행 결과 |
| 교차 검증 | 다른 조원 결과에서 확인한 사항과 근거 |
| 최종 시험 | 조건·예상 결과·실제 결과 |

- 모든 조원에게 담당 결과물과 검증 기록이 있어야 한다.
- 조별 완성도와 개인별 기여를 함께 확인한다.
- 기록만으로 확인하기 어려우면 담당 코드와 동작 설명으로 추가 확인한다.
- 자동 검증 기록은 실제 학생별 직접 수행을 입증하는 자료와 구분한다.

## 제출·평가 기준

Colab 안에 다음 내용을 모두 포함한다.

- 프로젝트 소개·적용 방식·해결할 문제
- 역할 분담표·조원별 완료 기준
- 자료·기존 코드·처리 또는 수정 기준
- 구현·수정 코드·실행 결과
- 반영 전후 비교
- 이름별 참여 기록
- 교차 검증·최종 시험 기록
- 최종 코드 위치·실행 방법

- 코드 출력이 표시된 상태로 저장한다.
- Colab 외 구현은 코드 위치·실행 방법·실제 동작 근거를 노트북에 포함한다.
- 연결된 저장소·자료·결과물의 열람 권한을 확인한다.
- 별도 보고서 대신 Colab 공유 링크 하나를 제출한다.
- 자료 수·분석 수·그래프 수의 일률적인 할당량은 없다.
- 평가 중심: 필요한 작업 선정, 실제 구현·수정, 검증 근거, 전후 개선, 조원별 기여

## 수정 시 확인 순서

1. 이 문서를 먼저 읽고 사용자 최신 요청과 대조한다.
2. 기능 변경 요청이 없으면 13개 실행 셀의 코드 내용은 유지한다.
3. STEP 1의 여섯 항목과 다섯 프롬프트의 필수 다섯 항목을 확인한다.
4. STEP 2~5 및 이름별 다섯 기록 항목을 확인한다.
5. HTML 원문·전체 미리보기·ipynb의 28개 셀 내용을 일치시킨다.
6. 설명·기준은 개조식, 비교는 표, 프롬프트는 담당별 말투, 결과 해석은 짧은 서술형으로 유지한다.
7. 실행 코드를 바꾸지 않았으면 문서 구조·동기화·문법을 확인한다. 코드를 바꿨으면 관련 시험과 통합 시험을 실행한다.
